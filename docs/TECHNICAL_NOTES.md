## Model & orchestration details

- **Registry** (`agent/registry.json`): `reason`=`claude-opus-4-8`, `draft`/`code`=`claude-sonnet-4-6`, `quick_tag`=`claude-haiku-4-5`, `critic`=`claude-opus-4-8`, `embed`=`@cf/baai/bge-base-en-v1.5` (768-dim). Costs are encoded per job (USD /Mtok) and used to compute `cost_usd` on every call.
- **Sampling:** Opus 4.8 / Sonnet 4.6 reject `temperature`/`top_p`/`budget_tokens` (400), so depth is steered with `output_config.effort` + adaptive thinking; Haiku is a plain call. Asserted in `tests/unit/registry.test.ts`.
- **Provider resilience** (`agent/retry.ts`, architecture.md §3.1): one call path means retry is added once and inherited by every skill, every gate call and every tool-loop turn. Retried: `429`, `500`, `502`, `503`, `504`, `529`, network faults, our own per-attempt aborts. Never retried: `400` and `401`, explicitly, because a `400` here means we sent a bad sampling param and must hear about it fast rather than three round-trips later. Bounded three ways: an attempt cap, a per-attempt `AbortSignal` timeout, and a whole-call deadline shared across the up-to-6 tool-loop turns so waits cannot compound. Backoff is exponential with full jitter; `Retry-After` is honoured but capped at 20s. Budgets are tuned per tier (Haiku 3 x 20s / 60s total, Sonnet draft 3 x 90s / 240s, Sonnet code 2 x 180s / 300s, Opus 3 x 120s / 300s). The SDK's `maxRetries` is set to `0` so there is exactly one retry layer, ours.
- **Retry vs. the budget:** tokens already billed on earlier tool-loop turns used to be discarded when a later turn threw, so failed runs never reached `agent_runs` and the daily guard undercounted. The partial metered record now rides out on the error (`MeteredProviderError` / `MeteredRunsError`) and `runSkill` writes it before rethrowing. A failed *attempt* contributes zero tokens, which is the honest number, not a guess.
- **One call path:** no skill talks to the SDK directly; `callModel` is the sole Anthropic entry point and has no send capability by construction. The primary answer path runs it through an embedded `@conduit/client` seam (`agent/conduit.ts`), a stable interface that can later point at a hosted gateway with no call-site changes; cost accounting is unchanged.
- **Dynamic difficulty routing** (`agent/routing.ts`): a deterministic, network-free classifier seeds a starting tier on a `quick_tag`→`draft`→`reason` ladder; trivial inputs route down, and a failing gate verdict or weak computed confidence escalates up. Bounded (cannot loop), metered every hop, and carried as a Conduit `pinModel`. Confidence is computed deterministically from gate signals (`computeConfidence` in `agent/quality-gate.ts`), and the `RoutingTrace` is persisted into `agent_runs.trace` on background/batch paths (not yet on the interactive routes).

## Guardrails (defense in depth)

1. Structural: no send tool + separate dispatch module + CI import ban.
2. Deterministic: no-send output-marker scan + voice blocklist (`inspectGuardrails`).
3. LLM-judge: voice critic + truth gate (fail-closed).
4. Data: RLS-coverage invariant, no-client-secret invariant, wellbeing invariant.
5. Operational: rate limiting, security headers, cost-budget alerting, bounded provider retry (`agent/retry.ts`).

## Cost posture

Quality-first budget (reasoning tier judges reasoning-tier drafts) with a hard safety net: rolling 24h `agent_runs` spend vs. a default $25/day budget, warn at 80%, structured alert lines for Workers Logs (`lib/cost-budget.ts`). Cost-per-journey is a first-class, queryable quantity. Retry is bounded per tier and metered like any other hop, so resilience cannot quietly inflate spend or hide it: the attempt cap is the ceiling on extra round-trips, and failed runs are still written.
